# Issue Resolver — Функциональная спецификация

> Документ описывает **что** делает приложение, а не **как** оно реализовано.
> Предназначен для воспроизведения на любом технологическом стеке (React, Vue, Svelte, vanilla JS, etc.).

---

## 1. Назначение системы

**Issue Resolver** — веб-интерфейс для запуска AI-агента, который автоматически решает задачи из Jira, работая с git-репозиториями. Пользователь указывает ссылку на Jira-тикет, репозитории и контекст; система создаёт задачу, запускает агента и позволяет отслеживать прогресс через итерации.

---

## 2. Навигационная структура (SPA)

Приложение — одностраничное (SPA) с фиксированным сайдбаром. Три экрана:

| Маршрут | Название | Описание |
|---------|----------|----------|
| `/new` (по умолчанию) | Новая задача | Форма создания задачи |
| `/tasks` | Мои задачи | Список всех задач |
| `/tasks/:id` | Детали задачи | Просмотр одной задачи и её итераций |

**Сайдбар** — фиксированная левая панель с двумя кнопками:
- «Новая задача»
- «Мои задачи»

Активная кнопка подсвечивается. Логотип «Issue Resolver» в верхней панели — кликабельный, ведёт на страницу создания задачи.

## 3. Страница «Новая задача»

### 3.1. Назначение
Форма для запуска новой задачи. После успешного создания пользователь перенаправляется на страницу деталей созданной задачи.

### 3.2. Поля формы

| Поле | Тип | Обязательное | Описание |
|------|-----|-------------|----------|
| Ссылка на Jira-тикет | `input[text]` | Да | URL задачи в Jira, например `https://jira.example.com/browse/KLA-5672` |
| Репозитории | Список карточек | Минимум 1 | Список git-репозиториев для клонирования |
| Дополнительный контекст | `textarea` | Нет | Произвольный текст с инструкциями для AI-агента |
| Протестировать результат | `checkbox` (toggle) | Нет | Включает запуск Reviewer-агента после Resolver |
| Контекст для Reviewer | `textarea` | Нет (условно) | Появляется только при включённом toggle. Описание сценария для проверки результата |

### 3.3. Карточка репозитория
Каждый репозиторий — это блок с полями:
- **Адрес репозитория** (`input[text]`, обязательно) — git URL, например `git@gitlab.example.com:files-web.git`
- **Исходная ветка** (`input[text]`, обязательно) — базовая ветка для клонирования, по умолчанию `dev`

Кнопка «+ Добавить репозиторий» добавляет новую карточку. Кнопка «Удалить» (появляется когда репозиториев >1) убирает карточку. Карточки нумеруются (Репозиторий 1, Репозиторий 2, ...).

### 3.4. Toggle «Протестировать результат»
- Кастомный switch (не нативный checkbox)
- При включении раскрывается блок с:
  - `textarea` «Контекст для Reviewer» (необязательный) — описание как воспроизвести сценарий, где искать, на что обратить внимание
  - Подсказка: «Reviewer также получит историю контекста всех итераций этой задачи»

### 3.5. Отправка формы
- Кнопка «Запустить» во всю ширину
- На время отправки: кнопка блокируется, текст меняется на «Запуск...»
- При ошибке: красный блок с текстом «Не удалось создать задачу»
- При успехе: редирект на страницу созданной задачи

### 3.6. API-запрос
```
POST {VITE_API_URL}/issue-resolver/api/v1/issues
Content-Type: application/json

{
  "jira_issue_url": string,
  "repositories": [
    { "repository_url": string, "base_branch": string }
  ],
  "additional_context": string,
  "review_context": string,        // пустая строка если reviewer выключен
  "is_review_need": boolean
}
```
Ответ: `{ id, jira_issue_url, created_at, updated_at }`

## 4. Страница «Мои задачи»

### 4.1. Назначение
Список всех ранее созданных задач с быстрым просмотром статуса.

### 4.2. Заголовок
- Заголовок «Мои задачи»
- Подзаголовок «История запусков Issue Resolver»
- Кнопка «Создать задачу» справа → переход на форму создания

### 4.3. Таблица задач

Колонки:
| Колонка | Описание |
|---------|----------|
| Задача | Ключ Jira-тикета (последний сегмент URL, например `KLA-5672`) + полный URL под ним |
| Репозитории | Имена репозиториев (извлечённые из URL, без `.git`) через запятую |
| Ветки | Имена веток через запятую |
| Статус | Цветной бейдж статуса |
| Создано | Относительное время: «только что», «N мин назад», «N ч назад», «N дн назад» |

Клик по строке → переход на страницу деталей задачи.

### 4.4. Статусы задач

| Статус | Метка (RU) | Цвет |
|--------|-----------|------|
| `pending` | В очереди | Жёлтый |
| `running` | В работе | Синий |
| `completed` | Завершено | Зелёный |
| `failed` | Ошибка | Красный |
| `cancelled` | Отменено | Серый |

### 4.5. Состояния
- **Загрузка**: текст «Загрузка...»
- **Ошибка**: текст «Не удалось загрузить задачи»
- **Пусто**: текст «Задач пока нет»

### 4.6. API-запрос
```
GET {VITE_API_URL}/issue-resolver/api/v1/issues
```
Ответ: массив объектов Issue (см. раздел 7).

## 5. Страница «Детали задачи»

### 5.1. Назначение
Детальный просмотр одной задачи: информация, итерации, логи.

### 5.2. Шапка
- Кнопка «← Мои задачи» — возврат к списку задач
- Название задачи (Jira-ключ)
- Бейдж статуса (цветной)
- Ссылка на Jira-тикет (открывается в новой вкладке)

### 5.3. Информационная сетка
Адаптивная сетка с карточками:
- **Репозиторий N** (по карточке на каждый): имя репозитория, полный URL, имя ветки
- **Создана**: дата и время создания (формат `DD.MM.YYYY, HH:MM`)
- **Обновлена**: дата и время последнего обновления

### 5.4. Секция «Итерации»

#### 5.4.1. Заголовок секции
- Заголовок «Итерации»
- Подзаголовок «История запусков задачи и дополнительный контекст для каждого запуска»
- Счётчик итераций (число в сером бейдже)

#### 5.4.2. Панель создания итерации
Блок «Новая итерация» с заголовком и подсказкой «Добавь новый контекст и запусти ещё одну попытку решения задачи».

**Индикатор доступности**:
- Если последняя итерация имеет статус `completed` или `failed` → «Можно запускать» (зелёный)
- В любом другом случае → «Запуск недоступен» (серый), все поля заблокированы

**Поля панели**:
- `textarea` «Контекст итерации» (обязательно для запуска). Placeholder: «Например: попробуй другой подход, обрати внимание на обработку ошибок и добавь тесты...»
- Toggle «Протестировать эту итерацию» — при включении:
  - `textarea` «Контекст для Reviewer» (необязательный). Placeholder: «Например: открой нужный экран, воспроизведи сценарий через UI и проверь конкретный network request...»
  - Подсказка: «Reviewer также получит историю контекста всех итераций этой задачи»

**Футер панели**:
- Подсказка слева:
  - Если запуск недоступен: «Новая итерация станет доступна после завершения текущей со статусом «Завершено» или «Ошибка».»
  - Если не заполнен контекст: «Укажи контекст для новой итерации.»
  - Если включён Reviewer: «После Resolver автоматически запустится Reviewer.»
  - Иначе: «Итерация завершится сразу после работы Resolver.»
- Кнопка «Запустить новую итерацию» → справа. Блокируется если: запуск недоступен, контекст пуст, или идёт отправка. При отправке текст «Создание итерации...»

#### 5.4.3. Список итераций
Каждая итерация — карточка:

**Шапка карточки**:
- Номер итерации в тёмном квадрате (1, 2, 3...)
- «Итерация #N» + подпись «Текущий запуск» (для последней) или «Предыдущий запуск»
- Бейдж статуса с цветной точкой

**Тело карточки**:
- Метка «КОНТЕКСТ» (заглавными, серым)
- Текст контекста (с сохранением переносов строк). Если пусто — «Дополнительный контекст не указан» курсивом
- Блок Reviewer:
  - Если Reviewer был включён: синяя точка + «Reviewer включён», под ним текст review_context
  - Если Reviewer не запускался: серая точка + «Reviewer не запускался»
- Футер: «Создана DD.MM.YYYY, HH:MM» и «Обновлена DD.MM.YYYY, HH:MM»

**Цвета левой границы карточки по статусу**:
- `pending` — жёлтый
- `running` — синий
- `completed` — зелёный
- `failed` — красный
- `cancelled` — серый

Текущая (последняя) итерация имеет усиленную тень.

### 5.5. Секция «Журнал логов»
- Заголовок «Журнал логов»
- Окно логов: тёмный фон, моноширинный шрифт, белый текст
- Строки лога: каждая начинается с `>>>`
- Пример содержимого:
  ```
  >>> Задача KLA-5672 создана
  >>> Получение данных из Jira
  >>> Jira-задача успешно загружена
  >>> Клонирование репозитория files-web
  >>> Репозиторий files-web успешно клонирован
  >>> Переключение репозитория files-web на ветку feature/KLA-5672
  >>> Запуск агента
  >>> Анализ проекта...
  ```

### 5.6. Состояния страницы
- **Загрузка**: кнопка «← Мои задачи» + текст «Загрузка...»
- **Ошибка**: кнопка «← Мои задачи» + текст ошибки
- **Задача не найдена**: «Задача не найдена»

### 5.7. API-запросы (два параллельных)
```
GET {VITE_API_URL}/issue-resolver/api/v1/issues/:id
GET {VITE_API_URL}/issue-resolver/api/v1/issues/:id/iterations
```

Создание итерации:
```
POST {VITE_API_URL}/issue-resolver/api/v1/issues/:id/iterations
Content-Type: application/json

{
  "context": string,
  "review_context": string,
  "is_review_need": boolean
}
```
Ответ: объект Iteration, добавляется в список с сортировкой по номеру.

## 7. Модели данных (API-контракт)

### 7.1. Issue (Задача)
```typescript
interface Issue {
  id: string;                    // UUID задачи
  jira_issue_url: string;        // Полный URL Jira-тикета
  repositories: IssueRepository[]; // Список репозиториев
  status: TaskStatus;            // Текущий статус
  created_at: string;            // ISO 8601
  updated_at: string;            // ISO 8601
}
```

### 7.2. IssueRepository
```typescript
interface IssueRepository {
  id: string;              // UUID
  repository_url: string;  // Git URL (HTTPS или SSH)
  branch_name: string;     // Имя рабочей ветки
  created_at: string;      // ISO 8601
  updated_at: string;      // ISO 8601
}
```

### 7.3. Iteration (Итерация)
```typescript
interface Iteration {
  id: string;              // UUID
  issue_id: string;        // ID родительской задачи
  number: number;          // Порядковый номер (1, 2, 3...)
  status: TaskStatus;      // Статус итерации
  context: string;         // Контекст, переданный пользователем
  review_context: string;  // Контекст для Reviewer (может быть пустым)
  is_review_need: boolean; // Нужен ли запуск Reviewer
  created_at: string;      // ISO 8601
  updated_at: string;      // ISO 8601
}
```

### 7.4. TaskStatus (общий для Issue и Iteration)
```typescript
type TaskStatus = 'pending' | 'running' | 'completed' | 'failed' | 'cancelled';
```

## 8. API-эндпоинты (сводка)

| Метод | Путь | Назначение | Тело запроса |
|-------|------|-----------|-------------|

### CreateIssueRequest
```json
{
  "jira_issue_url": "string (required)",
  "repositories": [
    { "repository_url": "string (required)", "base_branch": "string (required)" }
  ],
  "additional_context": "string",
  "review_context": "string",
  "is_review_need": false
}
```

### CreateIterationRequest
```json
{
  "context": "string (required)",

  "is_review_need": false
}
```

Базовый URL берётся из переменной окружения `VITE_API_URL` (на фронтенде) или аналогичного конфига.

## 9. Бизнес-логика и правила

1. **Имя задачи** извлекается из Jira URL как последний непустой сегмент пути (например, из `https://jira.example.com/browse/KLA-5672` → `KLA-5672`).

2. **Имя репозитория** извлекается из git URL: берётся последний сегмент после `/` или `:`, убирается `.git`.

3. **Новая итерация может быть создана только если** последняя итерация задачи имеет статус `completed` или `failed`. Если итераций ещё нет — создание разрешено.

4. **Контекст итерации обязателен** — кнопка создания заблокирована пока поле пустое.

5. **Относительное время** (на странице списка задач):
   - < 1 мин → «только что»
   - < 60 мин → «N мин назад»
   - < 24 ч → «N ч назад»
   - ≥ 24 ч → «N дн назад»

6. **Формат даты** (на странице деталей): `DD.MM.YYYY, HH:MM` в локали `ru-RU`.

7. **Toggle Reviewer**: при включении плавно раскрывается блок с дополнительным контекстом. При выключении — скрывается (`hidden`). Состояние сохраняется в форме.

8. **Список итераций** всегда отсортирован по номеру (поле `number`).

9. **Статус задачи** обновляется на статус только что созданной итерации после успешного POST.

10. **Race condition protection**: повторное нажатие кнопки создания итерации игнорируется пока предыдущий запрос не завершён.

## 10. Обработка ошибок

- **Ошибки сети / API** показываются в контексте действия:
  - Список задач: «Не удалось загрузить задачи»
  - Детали задачи: «Не удалось загрузить задачу»
  - Создание задачи: «Не удалось создать задачу»
  - Создание итерации: «Не удалось создать новую итерацию»
- Все ошибки логируются в консоль (`console.error`)
- AbortError (отмена fetch при размонтировании компонента) игнорируется

## 11. Нефункциональные требования

1. **Отзывчивость**: адаптивная вёрстка, три брейкпоинта (1200, 1000, 700px)
2. **Доступность**: семантический HTML (`<form>`, `<label>`, `<article>`, `<main>`, `<aside>`); focus-visible на интерактивных элементах
3. **Визуальная обратная связь**: переходы на ховер/актив (0.15s ease), сдвиг кнопок при нажатии
4. **Отмена запросов**: использование AbortController при уходе со страницы
5. **Скролл**: кастомный thin scrollbar в панелях; контентная область скроллится, сайдбар — нет

## 12. Глоссарий

| Термин | Значение |
|--------|----------|
| **Задача (Issue)** | Единица работы: Jira-тикет + репозитории + статус |
| **Итерация (Iteration)** | Один запуск AI-агента для задачи с конкретным контекстом |
| **Resolver** | Основной AI-агент, который решает задачу (пишет код) |
| **Reviewer** | Независимый AI-агент, который проверяет/тестирует результат Resolver |
| **Контекст** | Текстовые инструкции пользователя для AI-агента |
